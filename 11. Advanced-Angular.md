# Advanced Angular Interview Questions & Answers

> A guide covering 30 advanced Angular concepts for mid-to-senior developer interviews: performance, RxJS, architecture, DI internals, SSR, testing, and security.

---

## 1. How does Change Detection work internally with Zone.js?

Zone.js monkey-patches async APIs (`setTimeout`, events, XHR, Promises). When a task completes, `NgZone` emits `onMicrotaskEmpty`, and Angular runs `ApplicationRef.tick()`, which checks the component tree top-down, once per cycle, comparing template bindings with previous values.

In dev mode, a second pass runs to detect `ExpressionChangedAfterItHasBeenCheckedError`.

Run code outside Angular to avoid needless checks:

```typescript
constructor(private zone: NgZone) {
  this.zone.runOutsideAngular(() => {
    window.addEventListener('scroll', this.onScroll);
  });
}
```

## 2. What is zoneless change detection?

Angular can run without Zone.js (`provideZonelessChangeDetection()`, stable in recent versions). Change detection is scheduled when notified by: signal updates read in templates, `markForCheck()`, the `async` pipe, template event listeners, and `ComponentRef.setInput`.

```typescript
bootstrapApplication(AppComponent, {
  providers: [provideZonelessChangeDetection()]
});
```

Benefits: smaller bundles, better stack traces, fewer unnecessary checks. Components should be `OnPush`-compatible.

## 3. How does `OnPush` work and when does it re-check?

An `OnPush` component is checked only when:

1. An `@Input` reference changes
2. An event originates from the component or its children
3. `markForCheck()` is called or an `async` pipe emits
4. A signal read in the template changes

Mutating an object in place does **not** trigger a check — use immutable updates.

```typescript
this.items = [...this.items, newItem];   // triggers
this.items.push(newItem);                // does not
```

`detectChanges()` runs a check on this view now; `markForCheck()` marks ancestors dirty for the next cycle.

## 4. How do Signals differ from RxJS, and what are `computed`, `effect`, `linkedSignal`?

| Signals | RxJS |
|---------|------|
| Synchronous, always have a value | Push-based async streams, may have none |
| Fine-grained, glitch-free derived state | Event/time-based composition |
| No subscription management | Need unsubscribe |

```typescript
const price = signal(10);
const qty = signal(2);
const total = computed(() => price() * qty());         // lazy, memoized, read-only

effect(() => console.log('total', total()));           // side effects only

const selected = linkedSignal(() => this.options()[0]); // writable, resets when source changes
```

Avoid writing signals inside `effect` for state derivation; prefer `computed`/`linkedSignal`.

## 5. What are signal-based inputs, outputs, `model()` and queries?

```typescript
export class CardComponent {
  title = input.required<string>();
  size = input(10, { transform: numberAttribute });
  closed = output<void>();
  value = model(0);                       // two-way: [(value)]="x"
  header = viewChild<ElementRef>('header');
  items = contentChildren(ItemComponent);
}
```

They are readonly signals, work naturally with `computed`, and enable zoneless/OnPush-friendly code.

## 6. Explain the hierarchical Dependency Injection system

Angular has two injector trees: the **element injector** tree (components/directives, via `providers` and `viewProviders`) and the **environment injector** tree (root, route-level, lazy-loaded). Resolution walks up element injectors, then environment injectors, then the platform, and finally throws `NullInjectorError`.

- `providedIn: 'root'` — app-wide singleton, tree-shakable
- Route `providers` — per lazy route subtree
- Component `providers` — new instance per component
- `viewProviders` — not visible to projected content

## 7. What are `InjectionToken`, `useClass`, `useValue`, `useFactory`, `useExisting`?

```typescript
export const API_URL = new InjectionToken<string>('API_URL', {
  providedIn: 'root',
  factory: () => 'https://api.example.com'
});

providers: [
  { provide: Logger, useClass: ConsoleLogger },
  { provide: API_URL, useValue: '/api' },
  { provide: Cache, useFactory: () => new Cache(inject(API_URL)) },
  { provide: OldService, useExisting: NewService },       // alias, same instance
  { provide: HTTP_INTERCEPTORS, useClass: X, multi: true } // multiple values
]
```

Tokens are required for non-class values (strings, interfaces, config).

## 8. What are resolution modifiers (`@Self`, `@SkipSelf`, `@Optional`, `@Host`)?

- `@Optional()` — returns `null` if not found
- `@Self()` — look only in the current element injector
- `@SkipSelf()` — start from the parent injector
- `@Host()` — stop at the host component

```typescript
private parent = inject(ParentService, { optional: true, skipSelf: true });
```

Common for recursive structures (tree nodes) and avoiding self-injection.

## 9. What is `inject()` and the injection context?

`inject()` retrieves dependencies without constructor params. It works only in an **injection context**: constructors, field initializers, factory functions, functional guards/interceptors/resolvers, and `runInInjectionContext`.

```typescript
export const adminGuard: CanActivateFn = () => inject(AuthService).isAdmin();

runInInjectionContext(this.injector, () => inject(SomeService));
```

Calling it inside a method or async callback throws NG0203.

## 10. What is the difference between `switchMap`, `mergeMap`, `concatMap`, and `exhaustMap`?

| Operator | Behavior | Use case |
|----------|----------|----------|
| `switchMap` | Cancels previous inner; keeps latest | Search typeahead, route params |
| `mergeMap` | Runs all in parallel | Independent fire-and-forget calls |
| `concatMap` | Queues; preserves order | Sequential saves |
| `exhaustMap` | Ignores new while one is active | Login/submit button spam |

```typescript
this.search.valueChanges.pipe(
  debounceTime(300),
  distinctUntilChanged(),
  switchMap(term => this.api.search(term))
);
```

## 11. What are Hot vs Cold Observables, and what do `share`/`shareReplay` do?

- **Cold:** producer is created per subscriber (`HttpClient`, `of`) — each subscription re-runs the work.
- **Hot:** producer is shared (DOM events, Subjects).

```typescript
users$ = this.http.get<User[]>('/api/users').pipe(
  shareReplay({ bufferSize: 1, refCount: true })
);
```

`shareReplay` caches the last emission(s) for late subscribers; use `refCount: true` to avoid keeping the source alive forever.

## 12. How do you prevent memory leaks with subscriptions?

- Prefer the `async` pipe or signals via `toSignal`
- `takeUntilDestroyed()` (inside injection context or with `DestroyRef`)
- `take(1)` / `first()` for one-shot streams
- Remove manual listeners and timers in `ngOnDestroy`

```typescript
export class MyComponent {
  private destroyRef = inject(DestroyRef);

  ngOnInit() {
    this.data$.pipe(takeUntilDestroyed(this.destroyRef)).subscribe();
  }
}
```

## 13. What are Subjects, `BehaviorSubject`, `ReplaySubject`, and `AsyncSubject`?

| Type | Behavior |
|------|----------|
| `Subject` | Multicast; no initial value; late subscribers miss past values |
| `BehaviorSubject` | Requires initial value; emits current value to new subscribers |
| `ReplaySubject(n)` | Replays last `n` values |
| `AsyncSubject` | Emits only the last value on completion |

Expose subjects as `asObservable()` to keep `next()` private.

## 14. How do you handle errors and retries in RxJS?

```typescript
this.http.get<User[]>('/api/users').pipe(
  retry({ count: 3, delay: (err, i) => timer(2 ** i * 500) }),  // exponential backoff
  catchError(err => {
    this.notify.error(err.message);
    return of([]);                    // fallback
  })
);
```

An error terminates the stream; put `catchError` on the **inner** observable inside `switchMap` so the outer stream survives.

## 15. How do you interoperate between Signals and RxJS?

```typescript
import { toSignal, toObservable } from '@angular/core/rxjs-interop';

users = toSignal(this.http.get<User[]>('/api/users'), { initialValue: [] });
term = signal('');
results$ = toObservable(this.term).pipe(debounceTime(300), switchMap(t => this.api.search(t)));
```

`toSignal` auto-unsubscribes. Newer APIs like `httpResource` / `resource()` offer signal-native async data loading.

## 16. How does lazy loading and preloading strategy work?

Routes use `loadComponent` / `loadChildren` to split bundles. Preloading downloads lazy chunks in the background after startup.

```typescript
provideRouter(routes, withPreloading(PreloadAllModules));
```

Custom strategies (e.g., preload routes flagged `data: { preload: true }`) implement `PreloadingStrategy`. Combine with `@defer` for component-level splitting.

## 17. What are `@defer` blocks?

Declarative lazy loading of template parts, with triggers and placeholders.

```html
@defer (on viewport; prefetch on idle) {
  <app-heavy-chart />
} @placeholder (minimum 500ms) {
  <p>Chart placeholder</p>
} @loading (after 100ms; minimum 1s) {
  <app-spinner />
} @error {
  <p>Failed to load</p>
}
```

Triggers: `on idle`, `on viewport`, `on interaction`, `on hover`, `on timer(5s)`, `when condition`. Deferred components must be standalone.

## 18. What are functional guards, resolvers, and Router features?

```typescript
export const userResolver: ResolveFn<User> = (route) =>
  inject(UserService).get(route.paramMap.get('id')!);

{
  path: 'user/:id',
  component: UserComponent,
  canActivate: [authGuard],
  canDeactivate: [(c: UserComponent) => !c.dirty() || confirm('Discard changes?')],
  resolve: { user: userResolver }
}

provideRouter(routes, withComponentInputBinding(), withViewTransitions());
```

`withComponentInputBinding()` binds route params/data/query params directly to component inputs.

## 19. How do you build custom Reactive Form validators and `ControlValueAccessor`?

Validator:

```typescript
export function forbidden(re: RegExp): ValidatorFn {
  return (c: AbstractControl): ValidationErrors | null =>
    re.test(c.value) ? { forbidden: { value: c.value } } : null;
}
```

Async validators return `Observable`/`Promise` and run only if sync validators pass.

`ControlValueAccessor` lets a custom component work with `formControl`/`ngModel`:

```typescript
@Component({
  selector: 'app-rating',
  providers: [{ provide: NG_VALUE_ACCESSOR, useExisting: forwardRef(() => RatingComponent), multi: true }]
})
export class RatingComponent implements ControlValueAccessor {
  writeValue(v: number) {}
  registerOnChange(fn: (v: number) => void) {}
  registerOnTouched(fn: () => void) {}
  setDisabledState?(d: boolean) {}
}
```

Use typed forms (`FormControl<string>`, `NonNullableFormBuilder`) for type safety.

## 20. What is content projection (`ng-content`, `ng-template`, `ngTemplateOutlet`)?

```html

<header><ng-content select="[card-title]" /></header>
```


## 21. What are Host Directives and Directive Composition?

Apply directives to a component/directive from its own definition, exposing selected inputs/outputs:

```typescript
@Component({
  selector: 'app-button',
  hostDirectives: [{ directive: TooltipDirective, inputs: ['tooltip'] }, FocusableDirective],
  template: `<ng-content />`
})

```

Promotes reuse without inheritance.

## 22. How do you create dynamic components?

```typescript
@Component({ template: `<ng-container #host />` })
export class HostComponent {
  host = viewChild.required('host', { read: ViewContainerRef });

  load() {
    const ref = this.host().createComponent(AlertComponent);
    ref.setInput('message', 'Hi');
    ref.instance.closed.subscribe(() => ref.destroy());
  }
}
```

Alternatively, `*ngComponentOutlet` for declarative use. Dynamic components can be lazy-loaded via `import()` before creation.

## 23. How do you optimize Angular performance?

- `OnPush` + immutable data/signals, or zoneless
- `trackBy` / `track` in loops
- Lazy loading, `@defer`, preloading
- Pure pipes/`computed` instead of template method calls
- Virtual scrolling (`cdk-virtual-scroll-viewport`)
- `NgOptimizedImage` for images
- Run non-UI events outside zone
- Bundle analysis (`source-map-explorer`, `--stats-json`), tree-shaking, avoiding heavy libs
- SSR + hydration, HTTP caching
- Production builds (AOT, minification, budgets in `angular.json`)

## 24. What is Server-Side Rendering (SSR) and Hydration?

SSR renders HTML on the server for faster first paint and SEO (`ng add @angular/ssr`). **Hydration** reuses the server DOM on the client instead of re-rendering it.

```typescript
provideClientHydration(withEventReplay());
```

Related: static prerendering (SSG), incremental hydration (`@defer (hydrate on viewport)`). Avoid direct `window`/`document` access — use `isPlatformBrowser`, `afterNextRender`, or `DOCUMENT`. Use `TransferState`/HTTP transfer cache to avoid duplicate requests.

## 25. What is state management in Angular (NgRx, Signal Store)?

Options by complexity:

1. Services with signals / `BehaviorSubject` — small to medium apps
2. **NgRx Signal Store** — lightweight, signal-based
3. **NgRx Store** (Redux pattern): actions → reducers → store → selectors, with Effects for side effects, plus DevTools

```typescript
export const loadUsers = createAction('[Users] Load');
export const reducer = createReducer(initial, on(loadUsersSuccess, (s, { users }) => ({ ...s, users })));
```

Use a global store when many features share state, need time-travel debugging, or strict unidirectional flow.

## 26. How do you write unit tests for components and services?

```typescript
describe('UserComponent', () => {
  let fixture: ComponentFixture<UserComponent>;

  beforeEach(async () => {
    await TestBed.configureTestingModule({
      imports: [UserComponent],
      providers: [provideHttpClient(), provideHttpClientTesting()]
    }).compileComponents();
    fixture = TestBed.createComponent(UserComponent);
  });

  it('loads users', () => {
    const http = TestBed.inject(HttpTestingController);
    fixture.detectChanges();
    http.expectOne('/api/users').flush([{ id: 1 }]);
    expect(fixture.componentInstance.users().length).toBe(1);
  });
});
```

Tips: mock services with spies, use `fakeAsync`/`tick` or `waitForAsync` for async, `ComponentHarness` for Material components, and Playwright/Cypress for E2E. Runners: Karma/Jasmine, Jest, or Vitest.

## 27. How does Angular protect against XSS?

Angular treats all values as untrusted and **sanitizes** them by context (HTML, style, URL, resource URL). Interpolation is escaped automatically; `[innerHTML]` is sanitized.

Bypass only when truly safe:

```typescript
this.safe = this.sanitizer.bypassSecurityTrustHtml(html); // risky
```

Other protections: avoid building templates from user input, use AOT, CSRF/XSRF support in `HttpClient` (`withXsrfConfiguration`), Content Security Policy, and prefer `HttpOnly` cookies over `localStorage` for tokens.

## 28. What is Module Federation / Micro Frontends in Angular?

Splitting a large app into independently deployed remotes loaded at runtime into a shell. Implemented with Webpack Module Federation, or `@angular-architects/native-federation` (esbuild-friendly).

```typescript
{ path: 'orders', loadChildren: () => loadRemoteModule('orders', './routes').then(m => m.ROUTES) }
```

Challenges: shared dependency versions (singletons for Angular), shared state/auth, consistent styling, and versioning contracts. Monorepos (Nx) are the alternative for smaller teams.

## 29. What are Angular's build tooling and the esbuild/Vite builder?

The `application` builder (default since v17) uses **esbuild** for production builds and **Vite** for the dev server, giving much faster builds and HMR than the Webpack-based `browser` builder. It also supports SSR/prerendering in one pipeline.

Key `angular.json` settings: `budgets`, `optimization`, `sourceMap`, `fileReplacements`/environments, `assets`, `styles`, and `serviceWorker` for PWA.

## 30. What is the Ivy compiler and how does tree-shaking work?

Ivy (default since v9) compiles each component into instructions (`ɵɵelementStart`, `ɵɵproperty`, …) that are local to the component, rather than a global metadata interpretation. Benefits:

- Smaller bundles — unused framework features are removed (**tree-shakable** instructions and `providedIn` services)
- Faster incremental builds and AOT
- Better runtime debugging (`ng.getComponent`)
- Locality enabling lazy loading and `@defer`

Write tree-shakable code by using `providedIn: 'root'`, standalone components, and avoiding side-effectful imports.
